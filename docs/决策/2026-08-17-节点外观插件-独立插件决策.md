# 决策记录：DSH 节点外观插件（着色 + 隐藏）

> 日期：2026-08-17
> 状态：已决策
> 决策人：MaxNull
> 触发：当前会话面板各种节点（工具调用、智能体调用、联网搜索、指令执行等）全是灰色，难以辨认；需要可配置的节点着色；更进一步要"思考过程是否展示"的开关（前端隐藏即可）
> 关联：`docs/设计/DSH节点外观插件-设计方案.md`

## 〇、决策（2026-08-17）

**独立插件仓库 + npm 发布**：做 `@max-null/dsh-node-appearance`，不改 DSH 源码，cordis.yml 一行挂载；与已打通的 `@max-null/dsh-memory` 全链路（独立仓库 + npm + topic + PR）一致。

### 决策理由

1. **一切皆插件**：DSH 是插件化基座，会话节点的 DOM 已暴露稳定的着色钩子（`data-chat-flow-kind` / `data-tool` / `data-variant`），无需改核心。
2. **awesome 社区无同类插件**（2026-08-17 调研 [awesome-deepseek-harness](https://github.com/Dominic789654/awesome-deepseek-harness)）：
   - `renat3u/dsh-web-archive`：折叠思考/输出等噪声消息（只折叠，不配色、不可配置）
   - `jkcltc/dsh-chat-flow-re-layout`：纯 CSS 把工具调用折叠成 chips（无配置、无隐藏开关）
   - `GammaChineYov/dsh-collapsed-assistant`：折叠工具调用 + 彩色文件变更页脚（写死颜色）
   - `dmz2922990/dsh-thinkmeter` / `alingalingling/ui-status-label` / `Dbi-Eshuh/dsh-thinking-status-customizer`：只做思考状态样式/标签
   - 皮肤类插件（`moyang11111/DSH-`、`yoli-mi/dsh-client-ui-custom` 等）：整站换肤，不做节点级区分
   - **结论**：无"按节点类型/工具名着色 + 可配置配色 + 思考显示开关"的组合，差异化明确。
3. **配置方案取 settings 卡片而非 localStorage**：`dsh-skin` 注释称"第三方 namespace 会被 host 拒绝（settings-not-exposed）"，经核查当前版本 DSH 的 `settings.describe` 直接转发 `ctx.settings` 全部已注册 namespace，无 allowlist（`packages/host/apiproxy/src/api-proxy.ts` 3200 行 + 测试"serves every registered namespace, including one this repository never named"）。故采用官方 `installSettingsSection` + `settings.plugin.item` 卡片，配置进入用户 settings 文档（`$DSH_HOME/settings.yaml`），比 localStorage 正式且可随配置备份。
4. **命名涵盖两个功能**：插件不只有颜色，还有节点隐藏（思考过程开关），命名 `node-appearance`（节点外观）。

### 核心设计（详见设计方案）

1. 双面插件：Host half 注册 settings namespace（`node-appearance`）+ Config schema（初始化配色 + `showThinking`）；Browser half 注入 CSS 规则 + 设置卡片。
2. 着色钩子全部用 DOM data 属性（CSS Modules 哈希类名不稳定，不可依赖）：
   - 节点类型：`[data-chat-flow-kind]`（ChatNodeSeat 根）
   - 工具名：`[data-tool]`（ToolRow 根，wire 名）
   - 渲染变体：`[data-variant]`（`think` = 思考行）
3. 着色实现：CSS 自定义属性 `--ncolor-accent` + 通用渲染规则（左侧 3px 色条 `box-shadow: inset` 不占布局 + `color-mix` 淡色底），深/浅主题都成立。
4. 思考隐藏：`showThinking=false` 时追加 `[data-variant="think"] { display: none }`，纯前端隐藏。
5. 配置即时生效：settingsScope 快照订阅 → 重建 CSS 文本 → 更新 `<style data-plugin-css>` 标签。
6. 构建复刻 DSH 官方 `tsdown.client.ts` 产物格式（`window.__ModuleLoader__.load` 懒 CJS factory + CSS Modules 内联注入），该预设未发布 npm，独立复刻。

### 范围控制（v0.1）

- 只给行动类节点着色：工具调用/联网搜索/智能体调用/指令执行/文件操作/任务管理/命令节点/思考行；用户消息、普通回复、回合尾不着色（用户确认）。
- 自定义工具颜色覆盖：提供工具名 → 颜色条目增删。
- 不做：运行态动画、节点折叠、整站换肤（留给皮肤插件）。

### 护栏（防呆，非口号）

1. 失败回退：浏览器端 settings 快照未就绪或 schema 校验失败时回退内置默认配色，不白屏。
2. 与 DSH 兼容：不依赖任何 CSS Modules 类名；版本兼容面 = 平台模块（react/cordis/ui-slots 等）与 data 属性契约，均在 DSH 文档化范围内。
3. 发布前必跑：`npm test`（vitest）+ 手动浏览器验证（配色生效、开关生效、设置持久化）。

## 一、调研记录（2026-08-17）

### awesome 社区

见上"决策理由 2"。另记录：`jkcltc/dsh-chat-flow-re-layout` 的"纯 CSS zero build"思路与本文档的"DOM data 属性 + 注入 style"同源，但它不做可配置与隐藏。

### DSH 技术机制核验（源码）

| 机制 | 位置 | 结论 |
|---|---|---|
| client 插件加载 | `dsh-client-modules` 扫描 `dsh.client` 声明，serve `/plugins/<id>/client.js` | 独立仓库可用，cordis.yml 挂载即加载 |
| 节点 DOM 钩子 | `ChatNodeSeat`（`data-chat-flow-kind`）、`ToolRow`（`data-tool`/`data-variant`/`data-state`）、`ReasoningRow`（`data-variant="think"`） | 稳定，可 CSS 定位 |
| settings 无 allowlist | `api-proxy.ts` `settings.describe` 直接转发 `ctx.settings.describe()` | 第三方 namespace 可行（dsh-skin 注释已过时） |
| 设置卡片 | `settings.plugin.item` keyed slot，key = namespace | cookbook `adding-a-settings-card.md` 官方路径 |
| bundle 格式 | `window.__ModuleLoader__.load({id, factory})` + CSS Modules 内联注入 | `tsdown.client.ts` 未发布，独立复刻 |

### 备选方案与否决

1. **localStorage 存储配置**：dsh-skin 做法。否决：settings 机制已可行，配置进用户文档更正式、可备份。
2. **改 DSH 源码加 slot/API**：否决，违背"一切皆插件"，且无必要（data 属性够用）。
3. **整站主题 token 换色**（`--dsw-alias-*`）：只换全局色，做不到按工具名精确定位。否决。

## 二、验证计划

1. vitest 单测：CSS 规则生成（默认/覆盖/隐藏开关）、Config schema 默认值。
2. 手动验证（本地 dsh web）：加载插件 → 各类节点出现配色；设置页改色即时生效并持久化；关掉 showThinking 后思考行消失。
