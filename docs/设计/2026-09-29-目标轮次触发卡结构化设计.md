# 目标轮次触发卡 — 结构化设计

> 日期：2026-09-29
> 状态：待决策
> 关联：`docs/设计/DSH节点外观插件-设计方案.md`、`docs/决策/2026-08-17-节点外观插件-独立插件决策.md`
> 背景：SSiD 内核升级至 DSH 0.2.0-rc.1 期间提出

## 1. 问题

自主轮次（goal round）的通知卡把模型提示词原文吐给用户看，带着 `<goal_round>` / `Objective:` / `Round:` 这些提示词骨架：

```
[目标图标] 继续执行目标                                    13:42  ⌄
  这条通知触发了本轮的回复。

  <goal_round>
  Objective: "在隔离实例 (ssid-iso-test + home-100 profile) 里对比验证 better-sidebar…"
  Round: 1/256

  Continue working toward the objective in this same session. Treat the current workspace…
  </goal_round>
```

`Objective` 的一行 JSON 转义串横向顶出面板，`<goal_round>` 与那段英文指令对人不构成信息。用户要的是「这一轮在追什么目标、走到第几轮」，不是提示词的序列化形态。

## 2. 链路与「为什么官方这么显示」

| 环节 | 落点 |
|---|---|
| 提示词产生 | `packages/goal/goal-round-driver/src/prompt.ts:12` `renderGoalRoundPrompt()` |
| 来源标注 | 同包 `src/index.ts:178`，`source = { kind: 'goal', goalId, revision, round }` |
| 判为触发节点 | `packages/client/ui-chat/src/client/conversation-nodes/message.ts:118`（非人类来源 + 唤醒本轮 → kind `turn-trigger`） |
| 渲染注册 | 同包 `src/client/chat/register-node-renderers.ts:37` |
| 展开体 | 同包 `src/client/chat/TurnTriggerNodeView.tsx:46` → `NoticeBody` → `ModelFacingContent` |
| 原文落点 | 同包 `src/client/chat/ContextBody.tsx:147`，`<pre data-context-text>` |

官方不做解析是**刻意的**：`ModelFacingContent` 的职责原文是「把模型实际收到的文本、连同真实换行一起展示」，它是所有 context form 共用的兜底呈现。所以这不是缺陷，是那条原则在目标轮次上的副作用 —— **我们不能改内核，只能在这一格的渲染上另立规则**。

## 3. 为什么是接管

`conversation.chat.node` 是 keyed cell，`ChatNodeSeat.tsx:161` 以 `entryKey: node.kind` 渲染，ui-slots 的 `register()` 按 **priority 升序、最低者渲染**（同 key 同 priority 才抛错）。插件注册 `priority: -1` 即整体遮蔽官方的 `TurnTriggerNodeView`。

这是插件**已经在用的机制**（`ask_user_question`、`present` 两处 toolview 接管），不是新增姿势。

其余两条路径已淘汰：

- **纯 CSS 美化**：CSS 无法改文本内容，做不到摘掉 `<goal_round>` 与 `Objective:` 前缀 —— 而那正是本次要解决的问题。
- **在 `conversation.input.dock` 另加一条**：那是输入框上方（现有「目标详情」条所在位置），与「某轮被唤醒」这条会话流事件不是一个语义位置。

## 4. 设计

### 4.1 折叠态

```
[目标图标] 继续执行目标  [第 1 / 256 轮]              13:42  ⌄
```

在官方折叠头（图标 + 标题 + 时间 + chevron）上只加一件：**轮次徽标**。加它的理由是收起态本来只看得见「继续执行目标」，看不出走到第几轮；徽标让这一点无需展开即可读到。

徽标数据来自 `source.round`（结构化事实，不解析文本）。上限 `maxGoalRounds` 只能从文本 `Round: N/M` 的 M 得到，拿不到时降级为「第 N 轮」。

### 4.2 展开态

```
  这条通知触发了本轮的回复。                      ← 官方 message.trigger.explanation

  目标
  在隔离实例 (ssid-iso-test + home-100 profile) 里对比验证 better-sidebar
  的两套 WS 基建修复：PR #768 的 streamBaseUrl 方案、PR #706 的 webOrigin
  → trust-fence 方案。产出的可判定证据是：SSiD 形态下 /sidebar/ws/ 在地址
  修正后能否真正连上（opened），还是仍被 trust fence 403。

  ▸ 模型收到的指令                                ← 默认收起
```

三处取舍：

1. **目标原文不再走 `<pre>`**：改为正常排版的段落（正常字号、自动换行），不再是小字等宽 + 240px 内滚动。
2. **轮次不在展开区重复**：折叠头徽标已承载该数字，与 `goal-detail.tsx` 「两块不互相重复」同一原则。
3. **指令段折叠**：那段英文是给模型的执行要求，对人是噪音但**不该销毁** —— 它解释了「为什么模型这轮会这么干」，保留可查性才符合内核 ModelFacingContent 的本意。

### 4.3 字段来源：结构化优先，文本兜底

| 字段 | 首选来源 | 兜底 |
|---|---|---|
| 轮次 N | `source.round` | 文本 `Round: N/M` 的 N |
| 上限 M | 文本 `Round: N/M` 的 M | 不显示上限 |
| 目标正文 | 文本 `Objective: "…"` → `JSON.parse` | 整段原文回退 |
| 指令段 | 文本 `<goal_round>` 内 `Round:` 行之后的全部内容 | 不显示该节 |

提示词侧对目标做过 `JSON.stringify`，所以解析必须走 `JSON.parse` 才能还原转义（例如目标里含 `</goal_round>` 字样时它是被转义的，见 `goal-round-driver/tests/goal-round-driver.spec.ts:178-189` 的既有用例）。

### 4.4 非 goal 来源的等价外壳

遮蔽是**全 key** 的：注册 `turn-trigger` 的 `priority: -1` 会让全部 10 种触发来源（`goal` / `schedule` / `webhook` / `github` / `job` / `subagent` / `agent` / `team` / `plugin` / `request`）都走本插件组件。因此组件必须是**全 kind 实现**：

- 折叠头结构、图标映射（10 个图标全部来自共享 `ui-primitives`，0.1.7 与 0.2.0 两版均存在）、标题文案（`locale: 'chat'`，复用官方 `message.trigger.*` 字典）、时间格式，逐项与官方对齐；
- 仅 `source.kind === 'goal'` 且解析成功时切到 4.2 的结构化形态，其余一律渲染与官方同构的「explanation + 原文」；
- 保留官方 DOM 锚点 `data-turn-trigger`，以及既有样式所依赖的类名语义。

`formatMessageClock` 是 ui-chat 内部函数，跨插件不可 import（client 插件规则禁止 runtime-import 另一 feature plugin 的值），时间格式在插件侧按官方 `clock.md` / `clock.ymd` 两个 chat 字典键自行实现。

### 4.5 回退策略

解析必须**全有或全无**：`<goal_round>` 骨架、`Objective:` 行、`Round:` 行三者任一不符合预期（内核改了提示词格式、`maxGoalRounds` 为 undefined 导致文本出现 `Round: 1/undefined`、目标串 JSON 解析失败），即整卡退回 4.4 的等价形态，绝不显示半解析的字段。

理由与 `deliverable-model.ts`、`ContextBody.tsx` 的 `instructionChanges()` 同一条：**宁可显示原始事实，不给一个自信但不完整的卡片**。

## 6. 测试计划

- 解析：标准 `goal_round`、含转义字符的目标（`\n`、`"`、`</goal_round>` 字样）、`Round: N/undefined`、缺少 `Objective:` 行、非 goal 文本 —— 逐条断言「解析结果 or 整体回退」。
- 映射：10 种 kind 各自解析出官方同名的标题 key 与图标。
- 组件：非 goal kind 渲染出与官方同构的折叠头；goal 解析成功时展开体不含 `<goal_round>` 与 `Objective:` 字样。
- 门槛：`npm run typecheck` + `npm test` 全绿（L1）。

## 7. 已知限制与代价

- **官方的后续改进会被遮蔽**：0.2.0 就把 `schedule` 图标从 `IconAlarmClockOutlineRegular` 换成了 `IconClockOutlineRegular`；这类改动今后需插件侧手动跟进。与 `ask_user_question`、`present` 两处接管同一性质。
- **提示词格式是内核私有约定**：`<goal_round>` 结构变动不会触发任何门，只会让解析静默回退到原文形态 —— 回退本身是安全的，但"美化失效"不会被报出来。
- **10 种 kind 的外壳由插件维护**：官方新增触发来源时，插件需同步图标与标题映射，否则新 kind 会落到默认分支。

## 8. 待定

- 折叠态默认收起（与官方一致）还是对 goal 默认展开？当前设计取前者 —— 长会话里每轮插一条，默认展开会很吵，且轮次徽标已让收起态可读。
- 轮次徽标是否需要在接近上限时变色（如 `第 250 / 256 轮`）？当前不做，待有实际使用反馈再定。
