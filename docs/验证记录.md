**过程中发现并修掉的两处外观问题**（同日、实测后）：

1. **Turn 级摘要条不该套「块状行」的涂法。** 初版给它也上了 3px 左轨 + 内缩补偿，实测轨会**紧贴文字**，而补偿用的内缩又让它与上下所有行**错位**（2026-09-29 用户反馈"丑麻了"）。根因是内核把它渲染成**整行宽的分节线**（`padding: 0` + 底部发丝线），不是块状行。改法：**底线染色 + wash，不加轨也不内缩** —— 实测 `rail=(none)`、`borderBottomColor=rgb(148,163,184)`、`paddingLeft=0px`。对比过五种变体（含"加大内距"与"仅 wash"）后才定的这一种。
2. **过程组组头的轨贴图标。** 共享的 3px 内距是为块状行（图标有自身边距）量的，组头以图标起头时轨会压住字形。改为 8px，且**声明位置必须在共享涂色规则之后**（同特异性，靠后写取胜；挪到前面会被 3px 盖回去且不报错——已加断言守住顺序）。

**过程中修掉的一处缺陷**：Turn 级摘要条展开时缺 `padding-left` 补偿 —— 那是初版方案的补丁；第 1 条改用底线染色后，该补丁连同 `TURN_SUMMARY_OPEN` 常量一并删除，问题从根上消失。

**未验证**：装版（0.1.7-rc.2）上的表现未实测；本轮落点只覆盖隔离实例。0.1.7 与本插件的兼容性依据是源码比对（所用 DOM 锚点两版逐字相同），不是实测。

**目标轮次路径（实测）**：

- 折叠头 = `继续执行目标` + **`第 1 / 3 轮`** + `03:26`；收起态 5 个子元素（图标 / 标题 / 徽标 / time / chevron），官方是 4 个 —— 徽标是接管后唯一多出来的东西。

- **骨架零泄漏**：`<goal_round>` / `Objective:` / `Round:` 三项检测均为 `false`。
- `模型收到的指令` 默认收起（`details.open === false`），内容完整、可展开。

**非目标来源路径（实测 —— 接管全 key 的风险点）**：

造一条真实来源：让 dev 会话用 `pwsh` 起一个后台任务（`run_in_background`）→ 任务完成 → `tool-jobs` 通知唤醒一轮。结果：折叠头 `后台任务状态更新`（**无徽标** = 走了等价外壳），展开体 `[P, DIV]` 且含 `<pre data-context-text>`、无 `details`，原文完整显示，**未崩溃**。

**过程中踩到并修掉的坑**（都属于"不报错、只表现为插件没生效"）：

1. **props 路径写错**。官方读 `node.data.content` / `.source` / `.time`，第一版写成了 `node.*` → `new Date(undefined).toISOString()` 抛 `RangeError: Invalid time value`。**slot 系统会接住组件异常并静默回落到官方注册** —— 用户看到的只是"插件没生效"（卡片照常显示，只是官方样式），只有 console 里有一行 `slot entry crashed in 'conversation.chat.node'`。已在 `TriggerCardProps` 的 JSDoc 上写明这条，并给 durable 时间值加了非法值保护。
2. **落点更新后必须重启 host**（本节翻过一次车，见下）。`Remove-Item -Recurse` + 重建目录 → `client.js` 404、卡在 `Loading plugins…`；**就地覆盖文件也会 404**，而且症状更重：直接弹「应用无法启动或已意外停止 / `web boot: 1 entry did not activate` / `import failed`」，dev 实例卡死在启动页。
   **为什么一度以为"刷新即生效"**：那一次"只覆盖 client 半 + 刷新"确实成功了，但同一批覆盖里**顺手也覆盖了 `lib/index.js`**（host 半）——它的 mtime 变化触发了 host 重扫。单独覆盖 `lib/client.js` 时 host 察觉不到 → rev 对不上 → 404。**别把那次侥幸当规律。**
   判据：改完落点**一律重启 host**。停实例 = 杀掉命令行含 `.ssid-build\checkout` 的 electron（**绝不能按进程名杀**：宿主 `思灵.exe` 也在跑，那是当前会话的命）。
3. **`<pre>` 的换行要显式声明**（用户 2026-09-29 指出"换行就行，滚动条没必要"）。`PlainBody` 的 `<pre>` 漏了 `white-space: pre-wrap` —— `<pre>` 的 **UA 样式优先级高于继承**，只在外层 `.content` 上设是传不进去的；表现是正文横向溢出成一条长线（一条横向滚动条）。官方 `ContextBody.module.css` 的 `.text` 本来就有 `white-space: pre-wrap` + `overflow-wrap: anywhere` 两条，属漏抄。已补，实测 `preScrollW === preClientW`（无横向溢出）、正文折成 4 行。

**未验证**：装版（0.1.7-rc.2）上的表现；`schedule` / `webhook` / `agent-message` 等其余触发来源只由单测覆盖映射（10 种 kind），实机只跑通了 `goal` 与 `tool-jobs` 两条路径。
